# Localhost Manager

[Русский](README.ru.md) | [English](README.en.md)

Localhost Manager — desktop-приложение для управления локальными проектами и localhost-сервисами в Windows.

## Возможности

- Проекты и несколько localhost внутри каждого проекта
- Запуск, остановка и перезапуск localhost
- Пользовательские команды запуска
- Системный трей
- Избранные localhost
- Уведомления о запуске, остановке и критических ошибках
- Тёмная и светлая темы
- Русский и английский языки
- Запуск вместе с Windows
- Указание порта и URL
- Просмотр логов
- Сохранение проектов и настроек между запусками

## Скачать

Готовая версия для Windows x64 доступна в разделе [Releases](../../releases).

Скачайте архив:

`LocalhostManager-v0.2-win-x64.zip`

Распакуйте архив в удобную папку и запустите `LocalhostManager.exe`.

Приложение собрано как self-contained, поэтому для запуска не требуется отдельно устанавливать .NET 8 Runtime.

## Запуск из исходников

Для работы с исходным кодом требуется:

- Windows 10/11
- .NET 8 SDK
- Visual Studio 2022 или другой совместимый редактор

Клонируйте репозиторий:

```bash
git clone https://github.com/one4sv/Localhost-Manager.git
cd Localhost-Manager
```

Запустите приложение:

```bash
dotnet run --project LocalhostManager/LocalhostManager.csproj
```

## Сборка

Для Release-сборки:

```bash
dotnet build LocalhostManager/LocalhostManager.csproj -c Release
```

Для создания готовой самостоятельной версии Windows x64:

```bash
dotnet publish LocalhostManager/LocalhostManager.csproj -c Release -r win-x64 --self-contained true
```

Готовые файлы появятся в:

```text
LocalhostManager/bin/Release/net8.0-windows/win-x64/publish/
```

## Использование

### Создание проекта

1. Нажмите `Добавить проект`.
2. Укажите название и описание.
3. Сохраните проект.

### Добавление localhost

1. Откройте нужный проект.
2. Нажмите `Добавить localhost`.
3. Укажите название.
4. Выберите или добавьте команду запуска.
5. Укажите путь к папке проекта.
6. При необходимости укажите порт и URL.
7. Сохраните localhost.

После этого сервис можно запускать, останавливать и перезапускать непосредственно из приложения.

## Системный трей

В трее доступны:

- проекты;
- localhost;
- избранные localhost;
- запуск всех проектов;
- остановка всех проектов;
- перезапуск всех проектов;
- открытие приложения;
- настройки;
- выход.

Можно назначить до трёх избранных localhost для быстрого доступа.

## Изменения после v0.1

- Настройки → Автозапуск проектов: включите переключатель и отметьте нужные проекты.
  По умолчанию выключено. Изменения применяются при следующем открытии приложения,
  один раз за сеанс, независимо от способа запуска. Возврат из трея не запускает проекты повторно.
- «Запуск вместе с Windows» отвечает только за приложение; автозапуск сервисов настраивается отдельно.
- Статус процессов не сохраняется: старое `IsRunning` из JSON игнорируется.
- При восстановлении повреждённых данных автоматический запуск пропускается до следующего открытия.
- Новый главный экран: поиск по проектам, счётчики сервисов и обновлённые светлая/тёмная темы.
- Исправлено состояние при перезапуске; ошибки остановки отображаются пользователю.
- Логи ограничены последними 2000 строками, обновление пакетами каждые 100 мс.
- JSON записывается атомарно. Предыдущая версия хранится в `.bak`, повреждённый файл
  сохраняется как `.corrupt-<время>` и сопровождается предупреждением.

## Проверки

```powershell
dotnet run --project LocalhostManager.Tests/LocalhostManager.Tests.csproj -c Release
```

Проверки используют отдельную временную папку и тестовые процессы. Изображения интерфейса
сохраняются в `artifacts/screenshots`. Для изолированного запуска можно задать переменную
`LOCALHOST_MANAGER_DATA_DIR`; без неё используются обычные данные в `%AppData%/LocalhostManager`.

## Запуск и диагностика сервисов

На главном экране выберите проект слева. Справа доступны его сервисы и последние строки вывода. Кнопка «Логи» открывает поиск, копирование выбранных строк, экспорт видимых строк и паузу автопрокрутки. Сообщения stderr отмечены отдельно.

В форме сервиса выберите папку. Приложение предложит команды из package.json, проектов .NET и распространённых точек входа Python. Команду можно изменить перед сохранением.

В дополнительных настройках задайте порядок запуска (меньшие числа запускаются раньше), тайм-аут и HTTP-адрес проверки. Если задан только порт, используется TCP-проверка. Без адреса и порта интерфейс показывает только состояние процесса. При запуске проекта следующий сервис ждёт готовности предыдущего. Кнопка диагностики порта показывает имя процесса и PID.

Команда мягкой остановки необязательна. Без неё менеджер закрывает стандартный ввод и запрашивает закрытие окна. Если сервис продолжает работать, через 3 секунды менеджер завершает дерево процессов. Для сервисов с собственным механизмом завершения укажите штатную команду.

Автоперезапуск после сбоя включается отдельно для каждого сервиса. Задержки перед тремя попытками составляют 2, 4 и 6 секунд. История сбоев доступна в настройках. Повторное открытие менеджера возвращает существующее окно.

В настройках можно экспортировать конфигурации, импортировать их как дополнительные проекты или восстановить предыдущую резервную копию. Импортированные проекты получают новые идентификаторы сервисов и выключенный автозапуск. Восстановление заменяет список и сохраняет исходные идентификаторы.
